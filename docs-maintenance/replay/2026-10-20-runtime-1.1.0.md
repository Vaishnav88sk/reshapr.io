## Corrections established by execution

1. Script examples use API contract version `1.0.0`, independently of runtime `1.1.0`. Selectors and the cross-Service coordinate must not be mechanically upgraded to `1.1.0`.
2. The script timeout override must use the CLI's cached `docker-compose-1.1.0.yml`, not its older release path.
3. Script internal calls follow the declared Tool allow-list, not direct-client operation selection. Selecting only the four scripts still allowed the declared Todo lookup while hiding `get_todos_todoid` from `tools/list`.
4. Owner replacement accepts an unquoted username text body. Sending the formerly documented JSON string returned 404; `Content-Type: text/plain` with raw `platform-owner` returned 200 with the expected owner.
5. Standard quota updates preserve consumption and recalculate remaining capacity in 1.1.0. The prior claim that increasing a limit leaves remaining unchanged was false. The tagged `QuotaResource` confirms the observed calculation.
6. Public verification is page-wide. Following review on 2026-10-21, the original `Verified` product/version/date banner was restored. Release-review targets and partial replay notes are not displayed there; the notes above are private inputs to a future complete verification.

## Runtime interruption

On two runs, the proxy logged `Exposition changes stream has been terminated` and gRPC `UNKNOWN` while a new Exposition was propagated. The control plane logged that no Exposition was found for the same new ID. Subsequently the CLI listed the endpoint, but the proxy returned HTTP 404 for it. This report does not establish a root cause or claim that reconnection never happens.

A controlled restart of only `gateway-01`, followed by Compose readiness waiting, repopulated the registry and enabled the capability and script checks. The public affected guides link to the troubleshooting recovery step. This is a qualified replay result, not a fix to runtime propagation or a zero-downtime claim.
